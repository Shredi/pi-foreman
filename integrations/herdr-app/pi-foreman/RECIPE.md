# pi-foreman

An Agents list for the sidebar, grouped by space, that shows the pi-foreman session behind each agent: tier, cost, ask or waits, pull requests with their job state, nested sessions and agents. It replaces the shipped `agents` block of a cloned layout.

**What you see:** the shipped Agents list look (title "Agents" at 11.5px dim, space headers at 11px dim, agent rows 30px with program icon, name, machine, time in state and status glyph, footer "N agents · k need you"). Under an agent that is a foreman session, one tree and no second session row: the agent row carries tier (dim), summed cost and "N sessions"; a 20px ask, background or waits line under it (red while blocked); a wrapping line of PR chips (18px pills, raised background, border red when a job failed, `⎇ #n`, a red "!" when it conflicts, one two-part dot: spinning outer ring while a job runs, inner fill amber / red / green / dim) followed by a dim "N PRs · k failing · m pending" or "all green". The session's own agents and its child sessions are siblings, most urgent first: session rows 26px (name without a pi logo or "π", own cost, up to two chips, status on the right), agent rows 20px (small agent icon, role, muted and smaller, status on the right). 1px dim connectors join them (tee, rounded elbow, pass cell); every parent has a chevron that folds it and a folded row shows the most urgent status below. Resting on a chip opens a hover card (title, description excerpt, conflict line, jobs grouped failed / running / passed, capped); a click opens the PR. A final "Open PRs" section lists PRs nobody works on, one chip row per repo, and is hidden when empty.

**How it behaves:** working shows the spinner, blocked a red "Needs you" tag, running own agents (radar runs or `pi-subagents` records from `hc get`; also after the turn ended) a hollow spinner, done (no agents running) a filled dot, a background task a small square ("bg: name age"), a wait a hollow muted ring ("wait: note age"), idle a ring; ended sessions are hidden. Each running agent that radar does not already show (radar runs keep their agent row) is an agent row of its own (`title · msg`; at most 4, then `+N more`). Clicking an agent runs `pane.focus`; a live hc child runs `terminal.peek`, and a pane-less child (`hc run`) joined on `hcTerminal` is a full session in the tree, its nested sessions drawn once there; a chip with an https URL opens it with the platform opener. Radar is polled every 3 s (15 s per remote space); a poll lost for 45 s is started again, a radar exec is given up after 35 s, a failed read keeps the last data for 5 polls; then a dim "No foreman radar on <machine> (set props.foreman)" line shows and the poll retries every 30 s.

**Built from:** `herdr` `agents`, `terminals`, `focused`, `spaces`, `setAgentOrder`, `run`, `theme`, `exec`, `props`, `window`; `cx.timer.every`, `cx.spawn`. `model.js` is pure (parse, tree, join, rows, URL rule, opener argv) and has node tests. The only programs run: `foreman radar --json` (prop `foreman`, a path or an object keyed by machine with `local`), `hc get <terminal> --json` (polled for pi terminals) and the opener.

**Watch out:** join agents to radar nodes on `hcTerminal` (the `machine/` prefix for remote spaces), skip done nodes, require equal pids when both sides have one. Open only `https://` URLs without whitespace or `& | ^ < > " '`; call `hc` only as `hc get <terminal> --json` (argv, failures ignored), never write, never fetch. Never throw in render.

**Done when:** `herdr-app check` passes; with a radar that has a session in an agent terminal its rows appear under the agent; with no `foreman` the dim line appears; a bad URL never reaches the opener.

# pi-foreman

An Agents list for the sidebar, grouped by space, that shows the pi-foreman session behind each agent: tier, cost, ask or waits, pull requests with their job state, nested sessions and agents. It replaces the shipped `agents` block of a cloned layout.

**What you see:** the shipped Agents list look (title "Agents" at 11.5px dim, space headers at 11px dim, agent rows 30px with program icon, name, machine, time in state and status glyph, footer "N agents · k need you"). Under an agent that is a foreman session, one tree and no second session row: the agent row carries tier (dim), summed cost and "N sessions"; an ask line under it (red while blocked), else `⏳ note · age` (wait) or `⚙ name · age` (background) in dim small type; a wrapping line of PR chips (only for a PR whose head branch and head repository are the session's branch and repo; a merely watched PR has none; 18px pills, raised background, border red when a job failed, `⎇ #n`, a red "!" when it conflicts, one two-part dot: spinning outer ring while a job runs, inner fill amber / red / green / dim) followed by a dim "N PRs · k failing · m pending" or "all green" (it follows the chip states, reads "N PRs" without CI data, and drops merged or closed PRs). The root row is uncarded and keeps its filled header row when selected. Every non-root session is a bordered card (26px header row: name without a pi logo or "π", own cost, up to two chips, status on the right) that holds its status lines, chips and its own agent rows (20px, 🤖 and role, muted and smaller; no status circle inside a card, the header shows the state; agents directly under the root keep theirs); nested child cards follow outside it. A selected card gets the raised background and an accent border. One continuous 1px dim line (tee, rounded elbow, pass cell) runs from under the chevron through the status and chip rows to the last child; every parent has a chevron that folds it and a folded row shows the most urgent status below. Resting on a chip opens a hover card (title, description excerpt, conflict line, jobs grouped failed / running / passed, capped); a click opens the PR. A final "Open PRs" section lists PRs nobody works on, one chip row per repo, and is hidden when empty.

**How it behaves:** working shows the spinner, blocked a red "Needs you" tag, running own agents (radar runs or `pi-subagents` records from `hc get`; also after the turn ended) the same spinner, done (no agents running) a filled dot, a background task a small square (`⚙ name · age` line), a wait a hollow muted ring (`⏳ note · age` line), idle a ring; ended sessions are hidden. Each running agent that radar does not already show (radar runs keep their agent row) is an agent row of its own (`title · msg`; at most 4, then `+N more`). Clicking an agent runs `pane.focus`; a live hc child runs `terminal.peek`, and a pane-less child (`hc run`) joined on `hcTerminal` (else the terminal's foreground pid; done, ended and remote nodes and terminals already matched are skipped) is a full session in the tree, its nested sessions drawn once there; a chip with an https URL opens it with the platform opener. Radar is polled every 3 s (15 s per remote space); a poll lost for 45 s is started again, a radar exec is given up after 35 s, a failed read keeps the last data for 5 polls; then a dim "No foreman radar on <machine> (set props.foreman)" line shows and the poll retries every 30 s.

**Built from:** `herdr` `agents`, `terminals`, `focused`, `spaces`, `setAgentOrder`, `run`, `theme`, `exec`, `props`, `window`; `cx.timer.every`, `cx.spawn`. `model.js` is pure (parse, tree, join, rows, URL rule, opener argv) and has node tests. The only programs run: `foreman radar --json` (prop `foreman`, a path or an object keyed by machine with `local`), `hc get <terminal> --json` (polled for pi terminals) and the opener.

**Watch out:** join agents to radar nodes on `hcTerminal` (the `machine/` prefix for remote spaces), else by the terminal's foreground pid from the herdr `terminals()` record (live local nodes only: skip done, ended and remote nodes and nodes already matched); require equal pids when both sides have one. Open only `https://` URLs without whitespace or `& | ^ < > " '`; call `hc` only as `hc get <terminal> --json` (argv, failures ignored), never write, never fetch. Never throw in render.

**Done when:** `herdr-app check` passes; with a radar that has a session in an agent terminal its rows appear under the agent; with no `foreman` the dim line appears; a bad URL never reaches the opener.
